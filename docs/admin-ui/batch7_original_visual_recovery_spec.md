## 文档定位

本文档是 Admin UI Batch 7 的“原始视觉恢复版”设计方案，只描述设计目标、页面结构、视觉规则、交互体验和验收标准，不包含代码实现。

## 总体设计目标

Batch 7 的目标不是“让现有后台稍微好看一点”，而是把后台恢复为一套完整的 B2B 工业企业管理控制台。

核心体验目标：

- 让非技术运营人员知道“我正在编辑什么、会影响前台哪里、保存后如何检查”。
- 让表格、证书、询盘、资源等高频工作流具备清晰的主次层级和快速处理能力。
- 让后台在视觉上具有 Longxiang 品牌感、工业控制台气质和可信赖的企业级品质。
- 保持纯 HTML、CSS、Vanilla JS 技术栈，不引入框架。
- 不改变现有 API payload、数据库 schema 和 education 数据结构。

## 视觉方向

### 关键词

工业级控制台、可信、清晰、低噪音、高密度、可操作、非技术友好。

### 整体氛围

后台应呈现“电力设备企业内部运营控制台”的感觉，而不是普通模板后台。

视觉语言以深 navy 侧栏、白色工作面板、浅灰页面背景、蓝色操作色、少量金色品牌强调组成。页面应干净、克制、密度合理，但不能简陋。

### 禁止方向

- 不使用大面积渐变背景。
- 不使用装饰性光球、模糊斑块或营销页式视觉。
- 不把所有内容都包成卡片。
- 不使用过度圆角、过度阴影或塑料感组件。
- 不退回到“表格 + 简单按钮”的基础后台样式。

## 全局 Shell 恢复规格

### 左侧侧栏

参照图：`admin-ui-batch7-products.png`、`admin-ui-batch7-dashboard.png`

侧栏是第一版设计的品牌核心，必须恢复完整质感。

设计要求：

- 背景为深 navy，接近电力控制柜的沉稳质感。
- 顶部展示 Longxiang 品牌标识，黄色图形和蓝/白文字形成品牌记忆点。
- Logo 下方显示“网站后台管理系统”。
- 导航项带线性图标，图标与文字对齐。
- 一级模块包括：概况、产品、内容、证书、询盘、资源、系统。
- 可展开模块右侧有箭头。
- 当前一级模块有更亮的背景。
- 当前二级菜单使用蓝色高亮块和左侧强调。
- 询盘模块带红色未读数量 badge。
- 底部固定 Admin 用户区，包含头像、在线点、角色信息和展开箭头。
- 底部保留收起侧栏按钮。

侧栏不应只是普通菜单，应承担品牌识别、模块定位和系统状态感。

### 顶部 Header

参照图：全部 6 张图

顶部区域应轻量，服务于当前位置和快速操作。

设计要求：

- 左侧显示面包屑，例如“后台管理 / 产品 / 产品列表”。
- 面包屑下方显示页面标题和一句解释说明。
- 右侧显示当前页面主操作。
- 通用右上角包含语言、全局入口、通知、全屏或退出等图标。
- 主按钮使用蓝色实心，次按钮为白底描边。
- Header 不应占用过高空间，保持内容区优先。

### 主工作区

设计要求：

- 页面背景为浅灰。
- 内容面板为白底、细边框、轻阴影。
- 面板之间保持明确但克制的留白。
- 页面信息分为 Primary Zone、Action Zone、Support Zone。
- 主任务区域永远占据视觉中心，辅助信息靠右或靠下。

## 模块一：控制台 Dashboard

参照图：`admin-ui-batch7-dashboard.png`

### 设计目标

控制台不是简单统计卡片，而是后台关键运营状态总览。

### 页面结构

从上到下：

1. 顶部页面标题与快捷操作
2. 五张核心 stat-card
3. 中部三列运营面板
4. 底部快捷操作与系统状态

### Stat-card 区

五张卡片：

- 产品总数
- 推荐产品
- 产品分类
- 询盘总数
- 新询盘

每张卡片包含：

- 左侧大图标
- 主数字
- 中文标签
- 环比或状态提示

图标风格应轻量线性，颜色分别使用蓝、金、绿、红等语义色。卡片应有轻微阴影和明确边框，不要过度装饰。

### 待处理事项

左侧面板显示需要运营处理的事项，例如：

- 新询盘需要处理
- 询盘待回复
- 产品草稿未发布
- 资源库空间不足

每项包含：

- 红点或语义图标
- 标题
- 简短说明
- 右侧操作按钮或箭头

这是控制台的行动入口，不能只是文本列表。

### 产品分类统计

中间面板显示 donut chart。

设计要求：

- 中心显示总产品数。
- 右侧显示分类图例和占比。
- 底部显示趋势提示和详情入口。

如果后续不实现真实图表库，可用 CSS 或 SVG 近似，但视觉上必须保留环形统计结构。

### 最新询盘

右侧面板显示最近询盘。

每条记录包含：

- 客户头像或首字
- 客户姓名
- 公司名
- 简短主题
- 状态 badge
- 时间

状态 badge 要区分新询盘、待回复、已回复、已关闭。

### 快捷操作

底部快捷操作应是图标按钮组，不是普通文字链接。

建议入口：

- 新增产品
- 查看询盘
- 内容管理
- 证书管理
- 资源库
- 系统设置

### 系统状态

显示：

- 服务器状态
- 数据库连接
- 存储空间
- API 服务

每项包含图标、名称和状态值。正常为绿色，风险状态为黄色或红色。

## 模块二：产品管理

参照图：`admin-ui-batch7-products.png`

### 设计目标

产品管理应成为高密度但清晰的商品管理界面，支持筛选、批量操作和快速扫描。

### 页面结构

从上到下：

1. 页面标题与操作按钮
2. 筛选面板
3. 产品表格面板
4. 底部批量操作栏

### 顶部操作

右侧主操作：

- 新增产品
- 批量导入
- 刷新

新增产品为蓝色主按钮。批量导入和刷新为描边按钮。

### 筛选面板

筛选面板是独立白色容器。

包含：

- 搜索产品名称或型号
- 状态筛选 segmented control
- 产品分类下拉
- 推荐产品下拉
- 清除筛选按钮

筛选面板应横向排列，保证专业工具感。

### 产品表格

列结构：

- checkbox
- 产品
- 分类
- 状态
- 推荐
- 简介
- 更新时间
- 操作

产品列包含：

- 真实缩略图
- 产品名称
- 产品型号或 slug

分类使用彩色胶囊标签，不同产品类别可有不同浅色底。

状态：

- 已发布：绿色
- 草稿：黄色
- 已删除：红色，仅回收站或特殊状态出现

推荐列使用 toggle switch。

简介列最多显示两行，避免撑高表格。

操作列使用图标按钮：

- 查看
- 编辑
- 删除

所有图标按钮必须有 tooltip 和 aria-label。

### 行状态

- hover：浅蓝背景
- selected：左侧蓝色 rail 或整行浅蓝
- 批量选中：底部操作栏出现

### 批量操作栏

底部固定或 sticky。

显示：

- 已选数量
- 取消选择
- 批量发布
- 批量下架
- 删除
- 关闭栏按钮

删除按钮必须为红色，且与其他按钮保持明显距离。

## 模块五：内容管理

参照图：`admin-ui-batch7-concept.png`

### 设计目标

内容管理是 Batch 7 的核心。必须从“JSON 编辑器”恢复为“非技术用户可理解的内容编辑工作台”。

### 页面整体结构

三栏结构：

- 左侧：内容模块内部导航
- 中间：结构化编辑表单
- 右侧：保存状态、前台影响范围、编辑提示、快速操作

### 顶部区域

显示：

- 面包屑：内容 / 当前内容块
- 页面标题，例如“关于我们”
- 发布状态 badge
- 页面说明
- 右侧操作：预览页面、重新加载、保存更改

保存更改为蓝色主按钮。

### 前台位置 Banner

位置 banner 必须在编辑区顶部。

内容包括：

- 信息图标
- “此内容显示在网站【页面名称】页面【区域名称】”
- 查看前台页面按钮

不同内容块需显示不同位置说明。

### 左侧内容模块导航

以当前内容块为上下文，展示当前页面内部可编辑区域。

以“关于我们”为例：

- Hero 区域
- 内容段落
- 发展里程碑
- SEO 设置

选中项用蓝色浅底和左侧强调。

该导航是第一版内容管理体验的关键，不能简化掉。

### 中间结构化表单

表单应按前台页面区域组织，而不是按 JSON 字段机械排列。

每个区域为一个可折叠面板：

- 面板标题
- 前台区域说明
- 字段组
- 图片预览
- 字数提示
- 配置状态

字段要求：

- 中文字段标签
- 必要的英文/阿语字段并排或分组
- 图片字段带预览
- 字符数提示
- helper text
- 数组字段以卡片列表呈现，可新增、删除、排序

高级 JSON 只能放在折叠区，不得作为默认编辑方式。

### 右侧辅助栏

右侧辅助栏必须恢复，内容包括：

#### 保存状态

- 当前保存状态
- 最近更新时间
- 版本号

#### 前台影响范围

列出修改会影响哪些页面区域。

例如关于我们：

- 关于我们页面 Hero 区域
- 关于我们页面内容段落区
- 关于我们页面发展里程碑区
- 多语言版本

每项使用绿色点或状态图标。

#### 编辑提示

列出当前模块的填写规范。

例如：

- 图片建议宽度 1920px 以上
- 标题建议不超过 60 个字符
- 副标题建议不超过 120 个字符
- 发布后将在前台实时生效

#### 快速操作

包含：

- 复制当前内容
- 导出 JSON
- 恢复上一个版本

恢复操作使用危险或警示样式。

### 关联信息区域

内容编辑页面底部可以显示关联证书、关联资源或关联产品。

这部分让用户知道当前内容不是孤立字段，而是和网站其他资产有关。

## 模块七：状态与反馈统一

### 空状态

空状态不能只写“暂无数据”。

应包含：

- 图标
- 明确说明
- 下一步操作

例如：

- “还没有证书，点击右上角新增证书上传第一份证书。”
- “当前筛选没有结果，可以清除筛选后重试。”

### 加载状态

- 表格使用 skeleton rows。
- 表单使用字段级 loading 或整体 skeleton。
- 右侧详情面板加载时保留布局，不闪烁。

### 错误状态

错误信息应放在发生位置附近。

复杂错误使用 banner，包含：

- 错误原因
- 重试按钮
- 是否已保留草稿

### 保存状态

保存流程：

- 点击保存后按钮进入 loading。
- 保存成功后按钮旁显示“已保存 HH:mm”。
- 保存失败显示错误 toast 和字段错误。
- 版本冲突时提示重新加载，并保留本地草稿。

### Toast

Toast 文案应面向非技术用户：

- “内容已保存，前台页面会读取最新内容。”
- “保存失败，内容未更新。请检查红色提示或稍后重试。”
- “已移入回收站，可在回收站恢复。”

## 数据与约束

### 不可改变

- 不改数据库 schema。
- 不改公开网站接口。
- 不改变 content block API payload envelope。
- 不改变 education `body_json` 字段结构。
- 不新增 education 字段。
- 不引入前端框架。

### 可改变

- admin 页面结构。
- admin CSS。
- admin JS 的渲染方式。
- server/routes/admin 下已有后台管理接口的安全增强。
- 纯 UI 层字段拆分和重组。

## 最终成功标准

Batch 7 恢复成功应满足：

- 后台整体第一眼接近 6 张原始视觉图。

- 所有危险操作、保存状态、空/错/加载状态都有清晰反馈。
- 现有 API 和数据结构保持兼容。
